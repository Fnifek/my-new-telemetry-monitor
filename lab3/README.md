# ЛР3 — аппаратная часть ИС и АС

Модель измерительного модуля системы мониторинга телеметрии систем охлаждения.
Продолжает ЛР1 (архитектура) и ЛР2 (конвейер приёма 100 Гц): здесь появляется
аппаратный тракт «NTC → ADS1115 → ESP32 → кадр → AES-256-GCM → UART».

Физического комплекта разработчика на стенде нет, поэтому аппаратная часть
реализована как программная модель. Она воспроизводит нелинейность терморезистора,
разрядность и шум ADS1115, возраст отсчёта при многоканальном опросе, квантование
периода тахометра, формат кадра, CRC и накладные расходы AES-256-GCM.

## Что реализовано

- `NtcChannel` — делитель с NTC 10 кОм / B3950, прямое и обратное преобразование;
- `Ads1115Model` — 16-битное квантование, ±1 МЗР нелинейности, шум входа;
- `TachometerModel` — период импульсов, 1 мкс, джиттер, усреднение 4 периодов;
- `ThermalPlant` — тепловой процесс ЛР2 (Ньютон–Рихман, нагрузка 45/82 °C);
- `BoardModel` — собирает отсчёты и заполняет `TelemetryFrame`;
- `Aead` — AES-256-GCM через Windows CNG (BCrypt), тег 16 байт;
- `encode_frame` / `decode_frame` — 32-байтный открытый кадр и 60-байтный
  защищённый конверт;
- `--selftest` — 24 проверки, включая вектор NIST и подмену тега;
- `firmware_esp32.cpp` — та же логика для ESP32 через mbedTLS (не компилируется
  на хосте, это листинг прошивки).

## Архитектура

```
NTC Tвх/Tвых/Tвозд ──► буфер + ФНЧ 30 Гц ──► ADS1115 (I²C)
Тахо CPU/RAD ────────► защита входов ──────► GPIO34/35 (capture 1 мкс)
INA219 ──────────────► I²C 0x40 ───────────► U / I насоса
                                              │
                                              ▼
                                   ESP32: таймер 100 Гц
                                   кадр 32 Б + CRC-16
                                   AES-256-GCM (60 Б)
                                              │ UART 921600
                                              ▼
                                   HardwareSensor → конвейер ЛР2
```

`HardwareSensor` реализует тот же `ISensorSource`, что и `ModelSensor` ЛР2,
поэтому кольцевой буфер, дискретизация, КИХ N=4 и EMA N=7 не меняются.

## Сборка и запуск

```powershell
cd lab3\hw_model
powershell -ExecutionPolicy Bypass -File .\build.ps1
.\build\ctm_hw.exe --selftest
```

Примеры:

```powershell
.\build\ctm_hw.exe --simulate 120 --csv sim.csv
.\build\ctm_hw.exe --quant --csv quant.csv
.\build\ctm_hw.exe --tach --csv tach.csv
.\build\ctm_hw.exe --latency 360000 --csv latency.csv
.\build\ctm_hw.exe --freq
.\build\ctm_hw.exe --demo-frame
```

`--selftest` должен напечатать `24 passed, 0 failed`.

Требования: Windows (BCrypt/CNG), g++ с C++17 или CMake. На Linux модель
не соберётся без замены `Aead` на OpenSSL/mbedTLS.

## Связь с ЛР2

| ЛР2 | ЛР3 |
|---|---|
| `ModelSensor` | `BoardModel` + `HardwareSensor` |
| температура в °C | NTC + ADS1115, код АЦП |
| 12 бит, 0,0293 °C | 16 бит, 0,0017…0,0147 °C |
| нет тахометрии | 2 канала, 1 мкс |
| нет протокола | 32 Б + CRC + AES-GCM |
| 18 проверок в отчёте | 24 проверки в `--selftest` |

## Ограничения

- Это модель, а не драйвер: нет самонагрева NTC, дрейфа, ЭМП от импульсного
  питания и реальных потерь UART/Wi-Fi.
- `firmware_esp32.cpp` — листинг для отчёта; на хосте не компилируется.
- Secure boot/flash encryption не включены; это ЛР4 и production-настройка.
- PostgreSQL/libpqxx в ЛР3 не используются: модуль отдаёт кадры, запись — ЛР4.

Подробности — в `docs/` и в отчёте `Лабораторная_3_Пасечник_А_С_Малюх_Е_Г.docx`
(лежит в рабочей папке `lab3/`, в репозиторий не коммитится).
