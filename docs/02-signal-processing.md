# Обработка сигнала: от температуры до фильтра

## 1. Тепловая модель

Температура ядра приближается к цели по закону Ньютона–Рихмана. В дискретном виде:

```
T[k+1] = T[k] + (T_target[k] - T[k]) * (1 - exp(-dt / tau))
```

- `tau = 8 с` — постоянная времени охлаждения;
- `dt = 1 / 200 Гц = 5 мс`;
- `T_target` — 45 °C при малой нагрузке и 82 °C при полной, период 90 с (45 с + 45 с).

Поверх идеальной кривой добавляются:

1. **Колебания оборотов кулера** — `0,35 * sin(2*pi*0,12*t)`. Это медленный «горб»,
   который не должен полностью исчезать после фильтрации: он отражает реальное поведение
   системы охлаждения.
2. **Белый шум измерения** — нормальное распределение, СКО 0,35 °C. Имитирует погрешность
   датчика и АЦП.
3. **Сетевая наводка** — `0,7 * sin(2*pi*49,5*t)`. Частота чуть ниже 50 Гц, чтобы
   проверить, как КИХ с нулём на 50 Гц давит близкую помеху.
4. **Квантование АЦП** — 12 бит, диапазон 0…120 °C:
   `q = 120 / 4096 = 0,0293 °C`.
   Значение округляется до сетки `min + k*q` и ограничивается диапазоном.

Итоговый «сырой» отсчёт:

```
raw[k] = quantize(T[k] + ripple[k] + noise[k] + mains[k])
```

`ModelSensor::last_truth()` возвращает `T[k] + ripple[k]` — то, что мы хотим восстановить.
Именно с этим значением сравнивает `--verify`.

## 2. Почему 100 Гц

Тепловой процесс имеет постоянную времени 8 с, его спектр лежит ниже 0,05 Гц. По теореме
Котельникова достаточно долей герца. Частота 100 Гц взята с большим запасом:

- она совместима с ЛР3, где аппаратный модуль отдаёт кадры 100 Гц;
- на 100 Гц удобно строить КИХ с нулём на 50 Гц;
- запас по частоте позволяет видеть высокочастотные помехи, а не только медленный тренд.

Источник работает на 200 Гц. Это не удвоение «просто так»: два отсчёта на такт дают
потребителю выбор, а буфер сглаживает разницу скоростей. Потребитель берёт самый свежий
отсчёт, поэтому задержка не накапливается.

## 3. КИХ-усреднение

Фильтр с конечной импульсной характеристикой:

```
y[n] = sum_{j=0}^{N-1} b[j] * x[n-j]
```

Для равномерного среднего `b[j] = 1/N`. При `fs = 100 Гц` и `N = 4`:

- нули АЧХ на частотах `k * fs / N`: 25, 50, 75 Гц;
- на 49,5 Гц ослабление около `-36 дБ`;
- групповая задержка `(N-1)/2 = 1,5` отсчёта = 15 мс.

Реализация хранит скользящую сумму и `deque` последних `N` значений, поэтому обработка
одного отсчёта — O(1), а не O(N).

## 4. EMA

Экспоненциальное скользящее среднее:

```
EMA[n] = alpha * x[n] + (1 - alpha) * EMA[n-1]
alpha = 2 / (N + 1)
```

При `N = 7` `alpha = 0,25`. EMA:

- не требует истории;
- даёт меньшее запаздывание, чем среднее по окну;
- не имеет нулей АЧХ, поэтому давит высокие частоты монотонно, но слабее КИХ.

Групповая задержка EMA: `(1 - alpha) / alpha = 3` отсчёта = 30 мс.

## 5. Почему сначала КИХ, потом EMA

КИХ решает узкую задачу: вырезает наводку вблизи 50 Гц. EMA добирает остаточный шум.
Если поставить EMA первой, она «размажет» наводку по времени, и КИХ уже не сможет
вырезать её так чисто. Поэтому порядок в `make_filters()`:

```cpp
filters.add(std::make_unique<MovingAverage>(4));
filters.add(std::make_unique<EmaFilter>(7));
```

Суммарная групповая задержка: `1,5 + 3 = 4,5` отсчёта = 45 мс при 100 Гц. Это нужно
учитывать при привязке отфильтрованного значения к метке времени.

## 6. Выбор параметров

В отчёте ЛР2 сравнивались варианты:

| Вариант | N КИХ | N EMA | СКО, °C |
|---|---|---|---|
| Без фильтрации | — | — | 0,604 |
| Только КИХ | 4 | — | 0,182 |
| Только EMA | — | 7 | 0,168 |
| КИХ + EMA | 4 | 7 | 0,119 |
| КИХ + EMA (пример из методички) | 5 | 10 | 0,109 |

Вариант 5/10 даёт чуть меньшее СКО, но:

- окно 5 не имеет нуля на 50 Гц, наводка давится хуже;
- EMA с N = 10 добавляет задержку.

Поэтому выбран 4/7 — компромисс между СКО, подавлением наводки и задержкой.

## 7. Что проверяет `--verify`

`--verify` — синхронный режим:

```text
for each sample:
    raw = sensor.read()
    filtered = filters.process(raw.value)
    truth = sensor.last_truth()
    error_raw += (raw.value - truth)^2
    error_filtered += (filtered - truth)^2
```

В конце:

```
СКО = sqrt(sum(error^2) / N)
ослабление = 20 * log10(СКО_raw / СКО_filtered)
```

Такой режим не зависит от потоков и планировщика, поэтому его результаты воспроизводимы
при одном seed. Обычный режим `ctm_acq` проверяет работу потоков и счётчики, но не
считает СКО: в `Sink` нет истинной температуры.

## 8. Частотная характеристика

АЧХ КИХ:

```
|H(f)| = |sin(pi*f*N/fs) / (N*sin(pi*f/fs))|
```

При `f = 49,5 Гц`, `N = 4`, `fs = 100 Гц`:

```
|H| ≈ 0,0157  ->  -36,1 дБ
```

EMA на той же частоте добавляет около `-16,9 дБ`. Суммарно цифровой тракт даёт около
`-53 дБ`. Если добавить аналоговый ФНЧ ЛР3 (30 Гц, второй порядок), суммарное ослабление
доходит до `-62 дБ`, но это уже другой уровень системы.

## 9. Фактический результат в этом репозитории

При `--verify --duration 60 --seed 42` и прогреве 10 с получается:

- СКО до фильтрации — 0,605 °C;
- СКО после фильтрации — 0,126 °C;
- ослабление — 13,6 дБ;
- максимальная ошибка после фильтра — 0,52 °C.

Небольшое отличие от таблицы 4 (0,119 °C) объясняется seed, фазой наводки
и окном прогрева; на порядок величин и выбор фильтров это не влияет.
